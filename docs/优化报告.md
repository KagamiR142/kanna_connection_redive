# KCR 会战模块开源优化报告

> **模块**：`kanna_connection_redive`（环奈连结 R / KCR 2.0）  
> **报告日期**：2026-09-27  
> **优化原则**：**文案与功能不偏移** — 所有重构均为「移动代码、拆分模块」，未改 QQ 回复文本、Web API 路径与业务逻辑。

---

## 一、总览

本次优化将原本面向私有部署的单体代码，整理为可开源的模块化结构，覆盖 **Phase 0～Phase 6** 共六个阶段：

| 阶段 | 名称 | 状态 |
|------|------|------|
| Phase 0 | 文档体系与 CI 准备 | ✅ |
| Phase 1 | 开发者工具链 `devtools/` | ✅ |
| Phase 2 | 会战 QQ Handler 拆分 | ✅ |
| Phase 3 | 共享基础设施抽取 | ✅ |
| Phase 4 | WebUI 后端路由拆分 | ✅ |
| Phase 5 | 用户文档补全与中文命名 | ✅ |
| Phase 6 | 开源收尾（LICENSE、README、CHANGELOG） | ✅ |

**验证**：`python scripts/run_checks.py` → **41 项 pytest 全部通过**，文档链接检查通过，帮助文本同步检查通过。

---

## 二、核心指标对比（优化前 → 优化后）

| 指标 | 优化前 | 优化后 | 效果 |
|------|--------|--------|------|
| `clanbattle/__init__.py` 行数 | ~1488 行 | **60 行** | 减少 **96%**，仅保留 Service 注册与启动任务 |
| `webui/api.py` 行数 | ~1285 行 | **119 行** | 减少 **91%**，仅保留 app 装配与 uvicorn 启动 |
| 会战 Handler 组织 | 单文件 35+ 个 `@sv.on_rex` | **9 个域模块**（`handlers/`） | 按业务域查找，职责清晰 |
| Web 路由组织 | 单文件 34 个路由 | **4 个路由模块**（`routes/`） | auth / panel / member / admin_ops |
| 单元测试 | 无统一入口 | **41 项** pytest + GitHub Actions CI | 无 Hoshino 环境可跑核心解析测试 |
| 帮助文本维护 | 手改 `__init__.py` 内字符串 | `自动报刀帮助.qq.txt` → 脚本生成 | 单一数据源，防漂移 |
| 敏感数据入库 | 含真实 QQ、密码、群数据 | **已删除/脱敏** + `.gitignore` 强化 | 可安全公开仓库 |
| 文档文件名 | 英文（`quick-start.md` 等） | **全中文**（`快速上手.md` 等） | 符合中文文档规范 |
| 预览/样例图 | 分散在 `tools/`、蓝图目录 | 统一 `devtools/previews/` | 无需 Bot 账号即可生成 PNG |

## 三、分阶段优化详情

### Phase 0：文档体系与工程基础

**做了什么**

- 建立 `docs/` 四层结构：`user/`、`developer/`、`design/`、`deploy/`
- 历史蓝图归档至 `docs/backup/blueprint/`（只读，不参与 CI 链接检查）
- 新增 `pytest`、`pyproject.toml`、`.github/workflows/ci.yml`
- 新增 `scripts/run_checks.py`、`scripts/check_docs.py`、`scripts/sync_help_text.py`
- 新增 `CONTRIBUTING.md`

**效果**

- 文档与代码有明确对应关系（见 [`说明.md`](说明.md)）
- 每次提交可自动校验帮助文本、文档链接、核心单测

### Phase 1：开发者工具链 `devtools/`

**做了什么**

| 目录/文件 | 职责 |
|-----------|------|
| `devtools/previews/status.py` | 生成状态图样例 PNG |
| `devtools/previews/boss_query.py` | 查 1～5 样例图 |

| `devtools/fixtures/api/` | 脱敏 API JSON 样本 |
| `tools/generate_*.py` | 转发至 `devtools.previews.*`（兼容旧入口） |

**对比**

| 维度 | 优化前 | 优化后 |
|------|--------|--------|
| 预览脚本位置 | `tools/` + 蓝图 `preview/` 混杂 | 统一 `devtools/` |

**效果**

- 贡献者可本地验证 PNG 版式，无需部署完整 Bot
- README / 文档可引用固定命令：`python -m devtools.previews.status`

### Phase 2：会战 QQ Handler 拆分

**做了什么**

将 `clanbattle/__init__.py` 中 35 个指令 handler 迁至 `clanbattle/handlers/`：

| 文件 | 指令域 |
|------|--------|
| `help.py` | 自动报刀帮助 |
| `monitor.py` | 出刀监控启停（槽位 1/2/3/默认 **工厂合并**） |
| `reserve.py` | 预约、留言、预约表 |
| `apply.py` | SL、申请、挂树、掉刀、查树 |
| `query.py` | 状态、合刀、查 1～5 |
| `report.py` | 战报、催刀、KPI |
| `admin.py` | 清空申请、肃正、修正出刀 |
| `web_member.py` | 绑定本群公会、面板提示 |
| `context.py` | 共用工具（`extract_plain`、`sender_tag` 等） |

`__init__.py` 仅保留：

```python
register_role_commands(sv)
register_handlers(sv)
# + startup / cron
```

**对比**

| 维度 | 优化前 | 优化后 |
|------|--------|--------|
| 找「预约」相关逻辑 | 在 1488 行文件中搜索 | 直接打开 `handlers/reserve.py` |
| 监控槽位 handler | 4 段几乎相同代码 | `_register_start_handler` 工厂 |
| 新增指令 | 改上帝文件 | 在对应域模块 `register_*_handlers` 内添加 |

**效果**

- 代码审查范围缩小到单文件
- **所有 QQ 回复文案逐段迁移，未改字**

### Phase 3：共享基础设施抽取

**做了什么**

| 新模块 | 自何处抽取 | 用途 |
|--------|------------|------|
| `util/display/names.py` | `clanbattle/text_util.py` | QQ/游戏角色显示名 |
| `util/image/fonts.py` | `status_image.py`、`report_image.py` | PIL 字体加载统一 |
| `util/message_sanitize.py` | `command_parser.sanitize_remark` | 备注清洗（上移，parser 复用） |
| `webui/session.py` | `webui/util.py` | Cookie、主循环桥接 |
| `webui/permissions.py` | `webui/util.py` | 群内权限、`verify_group_access` |
| `webui/helpers.py` | `webui/api.py` | 档线响应、账号登录落库 |
| `webui/state.py` | `webui/api.py` | SSE 时间戳共享状态 |
| `docs/developer/数据目录.md` | 新建 | `resource/data/` vs `data/` 说明 |

**对比**

| 维度 | 优化前 | 优化后 |
|------|--------|--------|
| 字体加载 | `status_image` / `report_image` 各一份 | `util/image/fonts.load_font()` |
| Web 权限 | 混在 300+ 行 `util.py` | 独立 `permissions.py` |
| 显示名格式化 | 仅 `text_util` | `util/display/` + `text_util` 转发 |

**效果**

- 消除重复实现，降低 PNG 字体不一致风险
- `webui/util.py` 保持向后兼容（re-export）

### Phase 4：WebUI 后端路由拆分

**做了什么**

| 文件 | 路由 |
|------|------|
| `routes/auth.py` | `/login`、`/logout`、`/change_password`、`/home` |

| `routes/admin_ops.py` | 修正出刀、删队列、监控开关 |
| `routes/panel.py` | 仪表盘、通知、战报、SSE、面板、状态图、统计 |
| `routes/__init__.py` | `register_routes(router)` |

**对比**

| 维度 | 优化前 | 优化后 |
|------|--------|--------|
| `api.py` | 业务 + 装配 + 启动 | 仅装配 + 启动（119 行） |
| 修改登录 | 在 1285 行文件中定位 | `routes/auth.py` |
| URL / Cookie | — | **完全未改** |

**效果**

- Web 端与 QQ 端可并行维护不同路由文件
- FastAPI 路由注册模式统一，便于后续加中间件

## 六、行为与文案保证说明

以下项经刻意保持不变：

1. **QQ 指令**：正则、权限判断、回复字符串 — 从原 `__init__.py` **逐段复制**到 handler
2. **Web 登录**：Cookie 名、过期时间、改密规则 — 未改
3. **Web API**：路径前缀 `/kanna_dependency`、各端点 URL — 未改
4. **数据库 schema**：无破坏性迁移
5. **配置格式**：仍使用 `setting_clanbattle.json`（本地明文，按你的要求不加密）
