# 合刀线提醒（D 面报刀）

> 代码：`clanbattle/merge_line/`、`queue_display_service.build_damage_push_challenger_lines`

## 目的

D 面（周目 ≥23）且 Boss 剩余 HP 低于**合刀线**时，在监控报刀消息中提醒仍在挑战的已知玩家合刀；与 `合刀`/`cal` 计算器无关。

## 合刀线阈值

| 条件 | 阈值 |
|------|------|
| 该王有效整刀样本 &lt; 20 | **5e**（5×10⁹） |
| 首次满 20 刀 | 锁定当时 20 条样本，`(median+mean)/2×1.7` |
| 管理员重算单王 | 当期会战该王**最近** 20 条有效整刀，替换锁定样本 |
| 管理员 `重新计算合刀线a` / `A` | 1～5 王各重算一次 |

有效整刀：`knife_state=FULL`、伤害 ≥ **1.5e**、当期会战内。换期清空样本与阈值（开关保留，默认开）。

## 报刀消息结构（提醒开启且触发）

1. 可选前缀：`[合刀提醒{boss}-余{hp_e}-{n}人]`（`hp_e` 为亿、一位小数 + `e`；击杀固定 `0.0e`）
2. 常规报刀正文（首行、Boss 状态）
3. `目前有{n}人正在挑战：`（或 `（Boss内{k}人）` 见 [挑战队列](挑战队列.md)）+ 挑战者列表
4. 可选末尾两行（独立行）：先 `[CQ:at,qq=…]`（仅已知申请者，不含未知、不含本刀出刀者），再 `合刀线：{阈值hp_e}`

`n` 与挑战者列表行数一致（**含未知玩家**）；`@` 不含未知。

关闭提醒时：无 1、4，但第 3 步仍用**同一套**挑战者构建（见下）。

## 挑战者列表（报刀唯一入口）

`build_damage_push_challenger_lines` 与 `collect_damage_push_at_qq_ids` 共用同一套排除规则：

- 在 `on_settlement` **之前**读取申请队列 + 未知胶囊
- **始终显式排除**当前出刀者 QQ（击杀与非击杀相同；与 `on_settlement` 是否清队无关）
- `on_settlement` 语义：**击杀**才清空该王全部申请与未知；**非击杀**不会清空全队，仅扣出刀者绑定申请（或无绑 FIFO 一条）并进本信号 −1。报刀区人数 `n` 与列表不依赖上述副作用，只靠排除出刀者
- 击杀时 `on_settlement` 在报刀组装**之后**执行，避免若仅依赖清队会导致列表为空

## 指令

| 指令 | 权限 |
|------|------|
| `开启合刀线提醒` / `关闭合刀线提醒` | 管理员+ |
| `重新计算合刀线<1-5>` / `重新计算合刀线a` / `A` | 管理员+ |
