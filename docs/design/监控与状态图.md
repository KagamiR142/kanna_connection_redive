# 出刀监控与状态图

> 代码：`clanbattle/model.py`、`status_cache.py`、`status_service.py`、`status_image.py`

## 监控循环

每开启监控的群，默认 **每 1 秒** 一轮（`monitor.poll_min_sec` = `poll_max_sec` = 1）：

```
clan_battle/top
  → 覆盖 boss_info 镜像
  → 处理 damage_history 增量（报刀、预算、队列副作用）
  → 对每个 HP>0 的王 reload_detail_info
  → 更新 fighter_num、enter_signal
  → batch 结束：状态图指纹检查 → 异步 PIL 预渲染（至多 1 次）
```

多群受 `monitor.max_concurrent_groups` 与任务池限制。

## 报刀推送

监控发现新 `damage_history` 时群推送一条多行消息：

- 可选合刀线前缀（D 面、低于合刀线、开关开启，见 [合刀线提醒](合刀线提醒.md)）
- 首行：伤害、击杀前缀、刀型句
- 次行：当前 Boss 状态
- 挑战者区：`目前有{n}人正在挑战`（必要时 `Boss内{k}人`，`k` 来自 `enter_signal` 报刀侧扣本刀）+ 列表（`build_damage_push_challenger_lines`，`n` 为行数、排除本刀出刀者）
- 可选末尾：`[CQ:at,qq=…]` 与 `合刀线：…` **各占一行**

模板见 [指令规格 §3.4](../developer/commands/会战指令.md)。

其它自动推送：进本人数上升、预约 Boss 出现、挂树下树等（设计文档 backup §6）。

## 状态图预渲染

| 项 | 说明 |
|----|------|
| 目的 | QQ【状态】/ Web `status-image` **零等待**读 PNG |
| 数据源 | 只读 Boss 镜像 + SQLite + `challenge_state`；**禁止**为出图单独打 top |
| 更新 | 监控 batch 结束指纹变化 → 异步渲染；队列变更防抖合并 |
| 补偿倒计时 | 状态图 **不做** 秒级重绘 |
| 汇总 chip「整刀/补偿」 | 与「今日出刀」相同：`guild_today_knife_aggregate`（当日已出刀数，战报读侧去重后四态聚合） |
| 补偿详情列表 | `knife_budget` 未出补偿池，与 chip 分离 |

QQ【状态】：缓存命中直接发图；失败回退文本 `general_boss()`。
