# 整刀 / 补偿刀估算算法

> 代码：`knife_budget/settlement.py`、`classifier.py`、`comp_seconds.py`、`service.py`

## 四态

| 状态 | 消耗已用点 | 产生补偿 |
|------|-----------|----------|
| 整刀 | +1.0 | 否 |
| 击杀 | +0.5 | 是 |
| 补偿 | +0.5 | 否 |
| 补偿击杀 | +0.5 | 否 |

`damage_history` 结算后写入；`knife_settled_at` 锁定后不可被 `add_record` 覆盖。

## 刀型推测（未带 `b` 时）

**原则**：推测剩余 **宁可偏多，不可偏少**（避免误判账号无刀可出）。

规则摘要：

1. **击杀** 且已用整刀 < 3 → 判 **整刀**（占用整刀名额产补偿）
2. 否则若有可用补偿 → 判 **补偿**
3. 否则若已用整刀 < 3 → 判 **整刀**（未击杀）
4. 否则 → **异常**，记日志

用户可 `申请出刀1b` 显式补偿，或 `清空出刀点数` 纠正高估。

数学依据：在所有合法解释中贪心最大化「已产生补偿数」，保证推测剩余 ≥ 真实剩余。详见 backup 完整设计文档 §4.3～§4.4。

## 补偿秒数账本 \(R\)

**作用域**：同群 `(lap_num, order_num)` 为一个 Boss 实例。

| 时机 | 行为 |
|------|------|
| 新实例 | 用 top 的 `current_hp` 初始化 |
| 每条 history 入账前 | \(R\) = 当前账本剩余 |
| 未击杀 | `R ← max(0, R − damage)` |
| 击杀 | 处理后 `R ← 0` |

\(R\) 来源：本进程已处理 history + 已持久化 `RecordDao` 回放（跨重启）。

**与 top 展示 HP 分离**：补偿秒数认账本；top 仅展示。

### 击杀类型

| 类型 | 条件 | 秒数公式 |
|------|------|----------|
| 合刀击杀 | `D > R` | \(\min(90, \lceil 110 - 90R/D \rceil)\) |
| 收尾击杀 | `D == R` | \(\min(90, \max(21, 110 - T))\) |
