# 平台需求

## 身份与绑定

| 概念 | 存储 | 用途 |
|------|------|------|
| 监控账号 | `Account` | 私聊绑定 1～3 槽，登录游戏轮询 |
| 成员游戏身份 | `user_account` | 战报、申请队列展示、报刀归属 |
| Web 登录 | `WebAccount` | 浏览器 Session |
| 本群 Web 访问 | `ClanBattleMember` | 顶栏选公会；与 UID 绑定 **独立** |

**单管道原则**（`member_identity.py`）：

- 成员展示名、QQ 归属 **仅** 查 `user_account`
- 监控 `Account.viewer_id` 仅轮询；未绑 QQ 的出刀显示游戏名 +「监控」

管理员可在 Web **代绑** `user_account`（目标 QQ 无需先注册）。

## Boss 状态：以 top 为准

`clan_battle/top` 每轮返回：

- `boss_info[]` — **五王 HP/周目唯一权威**
- `damage_history[]` — 报刀、预算、清队列；**不**用于推算 HP

原则：

1. 须 **开启出刀监控** 才有实时 Boss / 状态图
2. 默认 **每 1 秒** 一轮：`top` → 处理 `damage_history` → 对 HP>0 的王 `reload_detail_info`
3. 【状态】/ Web 状态图读 **监控缓存**，不为单次请求打 top

## 指令语义摘要

### 预约 vs 申请

| | 预约 | 申请出刀 |
|---|------|----------|
| 绑定对象 | QQ 用户 | 游戏账号 |
| 目标 | **下一周目** Boss | 当前可挑战 Boss |
| 并发 | 每用户每王 1 条 | 每账号全群同时 1 条申请 |

### 权限（2026 定稿）

见 [developer/权限模型.md](../developer/权限模型.md)：KCR 超管 + 委派管理员；**不用** QQ 群管。

### 战报指令对调（KCR 2.0）

| 指令 | 产物 |
|------|------|
| `今日出刀` / `当期出刀` | 公会 **出刀次数统计** PNG |
| `今日战报` / `当期战报` | **名下** 四态明细 PNG |

日界：**05:00**。
