## 1. 通用约定

### 1.1 严格整句匹配

- 消息**首尾**允许空格；去掉首尾空格后，必须**整句**等于指令（或符合下文格式），否则不触发。
- 指令**主体**前不能夹带其它文字。  
  - ✅ `状态`、`  预约1周目15：刀伤300w  `  
  - ❌ `现在的状态`、`帮我预约1`、`进1号`
- 参数内部空格忽略（`预约 1 周目 15` 等价 `预约1周目15`）。

### 1.2 场景

| 场景 | 说明 |
|------|------|
| **群聊** | 绝大多数自动报刀指令 |
| **群聊 + 私聊** | `面板`、`网页端登录`（同义） |
| **私聊** | 监控账号绑定帮助、`刷新会战 Boss 元数据`（管理员+） |

### 1.3 参数符号

| 符号 | 含义 | 适用指令 |
|------|------|----------|
| `<boss>` | Boss 编号 1–5 | 含 Boss 参数的指令 |
| `[周目N]` | 可选；**必须**带 `周目` 前缀，如 `周目15` | **仅** `预约` |
| `[:留言]` | 可选；**必须**以 `:` 或 `：` 开头；冒号后至 `@` 前为留言 | 含留言的指令 |
| `[b]` | 可选；补偿刀标记 | **仅** `申请出刀/进`（**预约不含 b**） |
| `[账号编号]` | 可选；1–30 整数 | 见 §1.5 |
| `[@user]` | 可选；末尾 @ 一位群成员，代发 | 见 §1.4 |

**`[b]` 简要规则**：目标账号无可用补偿资源（`avail_comp` 与 `comp_seconds` 均为 0）时，视为未带 `b`；否则带 `b` 为显式补偿。未带 `b` 时刀型句与队列 `（补偿）` 仍可按当日 budget **推测**（详见设计文档 §5.3.3～§5.3.4、实施计划阶段 L）。

**`@sender`**：响应表中的占位符，表示「本条回复面向指令的实际发送者（操作者）」；**不**生成 CQ `@`。代发成功时业务对象是被 @ 的用户，但 `@sender` 仍指发消息的人。

### 1.4 末尾 @ 代发

可在**最末尾** `@` 一位群成员，使整条指令视为**被 @ 的用户**发送：

`预约` · `取消预约` · `申请出刀`/`进` · `取消申请`/`取消出刀` · `挂树` · `sl`/`sl?` · `今日战报` · `当期战报` · `掉刀`/`掉刀b`

**不允许代发**：`清空申请` · `清空出刀点数`（末尾 `@` 不切换身份）。

| 规则 | 说明 |
|------|------|
| 位置 | `@` 在指令**最末尾**（@ 后除空格外无其它文字） |
| 数量 | 仅**一位**；多个 `@` 时**最后一个**生效 |
| 留言截断 | 留言取 `:` 后至**最后一个 `@` 段之前** |
| @ 未生效 | CQ 无法解析或成员不在本群 → 不代发，按真实发送者执行 |
| 权限 | 代发**不**绕过管理员校验 |

### 1.5 账号编号

- 绑定顺序决定 **账号编号 1…N**（上限 30）。
- **未指定编号**：取第一个**今日仍有出刀点数余量**的账号；耗尽则顺延。
- **编号无效**：视为未携带，走默认逻辑。
- **预约、取消预约**不涉及账号编号。

### 1.6 预约 vs 申请（粒度）

| 维度 | 预约 | 申请出刀 |
|------|------|----------|
| 绑定对象 | **QQ 用户** | **游戏账号** |
| 并发上限 | 每用户每 Boss **最多 1 条** | 每账号全群**同时仅 1 条**进行中申请（**任意 Boss**，不可叠多个王） |
| 重复操作 | 同 Boss 再次预约 → **更新** | 该账号已有任意进行中申请 → **拒绝**（须先取消或换号） |
| 点数用尽 | — | 名下**全部**绑定账号今日点数均已用尽 → **拒绝**申请（见 §3.3） |
| 取消范围 | `取消预约<boss>` 按用户 | `取消申请` / `取消出刀` 清空该用户**名下各账号**的申请（可按 boss 过滤） |

### 2.2 预约

| 指令 | 格式 | 代发 |
|------|------|------|
| 预约 | `预约<boss>[周目N][:留言][@user]` | ✅ |
| 预约表 | `预约表` | — |
| 取消预约 | `取消预约<boss>[@user]` | ✅ |
| 清空预约 | `清空预约<boss>` | — |
| 留言 | `留言<boss>[:内容][@user]` | ✅ |
| 取消留言 | `取消留言<boss>[@user]` | ✅ |

> `预约` **不支持** `[b]`。`留言` 与预约区共用展示，**必须**带冒号及内容（支持 `:` / `：` / `﹕` / `︰`）；与 `取消预约` 不同，`取消留言` 仅撤销留言记录。预约对象为**下一周目** Boss；省略周目时 = 当前周目 + 1。指定 `周目N` 时 N 须 **大于** 该 Boss 当前周目（须已开启出刀监控）。详见设计文档 §5.2、§6.4。

| 指令 | 场景 |
|------|------|
| `面板` / `网页端登录` | 群聊 + 私聊 |

### 2.6 合刀计算器

| 指令 | 格式 | 场景 | 权限 |
|------|------|------|------|
| 合刀 / cal | `合刀<boss血量> <第一刀> [<第二刀>]` 或 `cal …` | 群聊 | 全员 |

**数值规则**（与 §3.6 一致）：

- `合刀` 与第一个数之间空格**可省略**；参数之间**必须**有空格；**第二刀可省略**（模板 D 或模板 E，见 §3.6）。
- 两参数时第二参数 **21～90**（或带 `s`/`秒` 后缀）→ **模板 E**（期望返还时间）；**≤20** → 模板 D（伤害）。
- 纯数字 **&lt; 100万** → 自动 ×1 万，展示时加 `w`。
- 后缀 **`w`** → ×1 万（不再因 &lt;100万 二次乘万）；后缀 **`e`** → ×1 亿。
- 补偿秒数：`s = min(90, ⌈110 − 90×R/D⌉)`（R = 后手结算前剩余血量）。

### 2.7 已废弃

`上树` → `挂树`；`下树` 无手动指令；`昨日出刀`/`昨日战报` → `当期*`；带昵称的 `今日战报` 固定为公会全员；`补申请出刀` → 合并进普通 `申请出刀/进`（未知玩家由申请顶位展示）。

## 3. 指令响应

**关于 `@sender`**：不发送 CQ `@`，仅文案占位（§1.3）。

### 3.1 帮助与监控

| 触发 | 条件 | 响应 |
|------|------|------|
| 自动报刀帮助 | — | 发送帮助全文 |
| 出刀监控 | 未绑定 | `@sender 无可用出刀监控账号，请添加机器人好友并私聊发送【绑定账号帮助】并配置监控账号` |
| 出刀监控 | 已绑定（冷启动） | `正在登录账号，请耐心等待。当前监控账号：{name}` |
| 出刀监控 | 切换槽位 | `正在登录槽位{n}账号（{name}），当前槽位{m}监控将保持至切换完成。` |
| 出刀监控 | 成功 | `@sender 出刀监控已开启…`（切换成功时首行含 `已由槽位{m}切换至槽位{n}`）<br>`当前监控账号：{name}，槽位{n}，#监控编号HN000{loop_num}` |
| 出刀监控 | 切换失败 | `槽位{n}账号登录/初始化失败，已恢复槽位{m}监控` |

| 出刀监控 | 失败 | `出刀监控失败次数过多，请重绑账号或手动检查账号登录状态`<br>`错误信息：{error_messages}` |
| 取消出刀监控 | 未开启 | `出刀监控功能未启用` |
| 取消出刀监控 | 权限不足 | `您的权限不足，请联系管理员` |

| 状态 | 成功 | **会战状态 PNG**（监控开启且缓存就绪；失败时回退 `general_boss()` 文本） |

### 3.4 报刀推送（监控自动）

监控检测到新 `damage_history` 时，群内推送**一条**多行消息（不因未绑定 QQ 跳过）。

**首行（已绑定 Web 成员）**

```
多账号：`{QQ昵称}-{账号编号}-{游戏名}对…`；单账号：`{QQ昵称}对{lap}周目{boss}王造成了{damage}点伤害，{击杀前缀}{刀型句}。
```

**首行（无 QQ 成员绑定）**

```
{游戏名}对{lap}周目{boss}王造成了{damage}点伤害[，{击杀前缀}{刀型句}]。
```

| `{击杀前缀}` | 条件 |
|--------------|------|
| `成功击杀并获得了{n}秒的补偿。` | 整刀击杀产补偿：**合刀**（伤害 `D` > 结算前剩余 `R`，§1.3.3）→ `{n}` 用 `90R/D` 式；**收尾**（`D==R`）→ `{n}` 用 `110−battle_time`（§1.3.4） |
| `成功击杀，未能获得补偿。` | 补偿刀击杀收尾 |
| （空） | 非击杀 |

`R` 为设计文档 §1.3.2 按本王本周目**已结算伤害回放**后的剩余，与 top 展示 HP、与合刀计算器参数 `H`（满血或假设血量）不是同一概念。

**后续行（共用）**

```
当前{boss}王状态：{lap}周目{hp_short}（{current_hp}/{max_hp}，{percent}%）
目前有{n}人正在挑战：
{挑战者列表…}
```

（或 `目前有{n}人正在挑战（Boss内{k}人）：`，规则同 §3.3.1。）

| 报刀挑战者区 | `build_damage_push_challenger_lines`：结算**前**申请+未知，**始终排除本刀出刀者**（与击杀/非击杀、`on_settlement` 是否清队无关）；`n` 与列表行数一致（含未知）。`on_settlement` 在报刀组装**之后**：击杀清全队，非击杀不清空全队。 |

**合刀线提醒**（D 面、开关开、HP 低于合刀线或击杀）：可选前缀 `[合刀提醒{boss}-余{hp_e}-{n}人]`；消息**末尾**独立两行——先 `[CQ:at,qq=…]`（已知申请者，排除出刀者），再 `合刀线：{hp_e}`。规则见 [design/合刀线提醒.md](../../design/合刀线提醒.md)。

**其它自动推送**（非报刀）：进本上升沿

```
{boss}王当前有{y}人出刀，申请队列中有{z}人：
{挑战者列表…}
```

| 字段 | 规则 |
|------|------|
| `{y}` | **`enter_signal`**（当次上升沿累加后的值；非接口 `fighter_num`） |
| `{z}` | 挑战者列表行数（§5.3.5，含申请、未知等；与 `{y}` 可不等） |

报刀推送中 `Boss内{k}人` 的 `k` 在组装时按「本刀已结算离开 Boss」计：`k = max(0, enter_signal − 1)`（击杀为 `0`），与随后执行的 `on_settlement` 一致。`sl` / `掉刀` 亦使 **enter_signal −1**。见 [挑战队列](../../design/挑战队列.md)。预约 Boss 出现提醒、挂树下树等见设计文档 §6。

### 3.6 合刀 / cal

| 触发 | 条件 | 响应 |
|------|------|------|
| 合刀/cal | 格式错误 | `@sender 指令格式错误`<br>`合刀格式：合刀<boss血量> <第一刀伤害> [<第二刀伤害>]`<br>`或：cal<boss血量> <第一刀伤害> [<第二刀伤害>]`<br>`合刀与第一个数之间的空格可省略；参数之间必须有空格。`<br>`数字小于100万自动×1万（展示加w）；末尾w表示×1万；末尾e表示×1亿。`<br>`例：合刀600 320 330 / 合刀3600 2950 / cal 43238 35600 25000` |
| 合刀/cal | 仅两参数，第二参数 ≤20（伤害） | 模板 D |
| 合刀/cal | 仅两参数，第二参数 21～90（或 `Ns`/`N秒`，秒数须在 21～90） | 模板 E |
| 合刀/cal | 秒数越界（带 `s`/`秒` 且不在 21～90） | `@sender 指令格式错误`<br>`期望返还时间须在 21～90 秒之间（例：合刀 6000w 21 或 合刀6000w 90s）` |
| 合刀/cal | 常规合刀（两刀均未单杀，且两刀之和 ≥ Boss 血） | 模板 A |
| 合刀/cal | 两刀之和 &lt; Boss 血 | 模板 B |
| 合刀/cal | 某一刀 ≥ Boss 血 | 模板 A 前两行 + 模板 C（该刀先出） |

**模板 A（常规）**

```
boss血量={H}
对boss伤害={刀1} | {刀2}
若{刀1}先出，{刀2}后出，补偿{s1}秒。[若需要满补，另一刀至少需要{D1}]
若{刀2}先出，{刀1}后出，补偿{s2}秒。[若需要满补，另一刀至少需要{D2}]
```

方括号内仅当 `{s}` &lt; 90 时出现。`{D} = ⌈90×R/21⌉`（\(R\) 为先手后剩余血量，整数伤害；展示规则同 §2.6）。

**模板 B（收不满）**

```
boss血量={H}
对boss伤害={刀1} | {刀2}
剩余{H-刀1-刀2}
```

**模板 C（单刀可击杀，该刀先出）**

```
若{刀X}先出，可直接击杀boss。若想获得满补，另一刀伤害不能低于{垫刀线}
```

`{垫刀线} = boss血量 − (该刀伤害 ÷ (90/21))`（向上取整到整数伤害后按 §2.6 展示）。

**模板 D（单刀参，省略第二刀）**

```
boss血量={H}
对boss伤害={刀1}
若{刀1}先出，后出刀需{D1}伤害可满补
若{刀1}后出，先出刀需{D2}伤害可满补
```

`{D1} = ⌈90×(H−刀1)/21⌉`；`{D2} = ⌈H − 刀1×21/90⌉`（均为整数伤害后按 §2.6 展示）。

**模板 E（期望返还时间，省略第二刀且第二参数为秒数）**

```
boss血量={H}
期望返还时间={S}
刀数 || 所需伤害
1刀      {D1}
2刀      {D2}
3刀      {D3}
```

`{D_n} = ⌊90×H / ((111−S) + 90×(n−1))⌋`（整数伤害后按 §2.6 展示）；固定计算 1～3 刀。

**示例**（`合刀576885 90`）

```
boss血量=576885w
期望返还时间=90
刀数 || 所需伤害
1刀      2472364w
2刀      467744w
3刀      258306w
```

**示例**（`合刀600 320 330`）

```
boss血量=600w
对boss伤害=320w | 330w
若320w先出，330w后出，补偿34秒。若需要满补，另一刀至少需要1200w
若330w先出，320w后出，补偿35秒。若需要满补，另一刀至少需要11571429
```

**示例**（`合刀3600 2950`）

```
boss血量=3600w
对boss伤害=2950w
若2950w先出，后出刀需27857143伤害可满补
若2950w后出，先出刀需29116667伤害可满补
```
