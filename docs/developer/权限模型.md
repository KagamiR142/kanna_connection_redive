# 权限模型

KCR 会战使用 **独立的 RBAC**，与 QQ 群管、Hoshino `SUPERUSERS` **解耦**。

实现入口：

- `rbac.py` — 角色判定、委派管理员 CRUD
- `clanbattle/permissions.py` — QQ 指令权限辅助
- `clanbattle/decorators.py` — `require_ops_admin`、`check_monitor_account`
- `webui/util.py` — Web 请求鉴权

---

## 角色定义

| 角色 | 判定条件 | 人数 |
|------|----------|------|
| **超级管理员** | `setting_clanbattle.admin_qq` | 1 |
| **委派管理员** | 超管私聊任命，存 DB `kcr_delegated_admin` | ≤5 |
| **普通用户** | 其余 QQ | — |

**管理员+** = 超级管理员 ∪ 委派管理员。

**不再使用**：`admin_qqs[]` 配置项（仅首次迁移进 DB）、QQ 群管、`priv.ADMIN` 作为会战运维权限。

权限不足统一文案：`您的权限不足，请联系管理员`（部分场景末尾加 `@sender`）。

---

## QQ 指令权限矩阵（会战）

| 能力 | 普通用户 | 管理员+ | 超管 |
|------|:--------:|:-------:|:----:|
| 状态、战报、预约、申请、合刀 | ✅ | ✅ | ✅ |
| 开启出刀监控、绑定监控账号 | ❌ | ✅ | ✅ |
| 取消出刀监控 | ❌ | ✅ | ✅ |
| 清空预约/申请/未知申请 | ❌ | ✅ | ✅ |
| KPI 调整、清空 KPI | ❌ | ✅ | ✅ |
| 修正出刀 | ❌ | ✅* | ✅ |
| 启用肃正协议 | ❌ | ❌ | ✅ |
| 任命/撤销管理员 | ❌ | ❌ | ✅ |
| 刷新会战元数据（私聊） | ❌ | ✅ | ✅ |

\* 以当前 handler 装饰器为准，维护时查 `clanbattle/__init__.py` 与 `decorators.py`。

### 监控特殊规则

- **关闭监控**：仅管理员+，监控发起者本人 **不能** 单独关闭。
- **监控账号绑定**：私聊，仅管理员+。

### 代发 @

末尾 `@` 代发 **不绕过** 管理员校验；业务用户切换为被 @ 者，`@sender` 仍为操作者。

---

## Web 权限矩阵

| 页面/操作 | 普通用户 | 管理员+ | 超管 |
|-----------|:--------:|:-------:|:----:|
| 会战面板、个人数据、统计数据 | ✅ | ✅ | ✅ |
| 管理运维 | ❌ | ✅ | ✅ |
| 会战面板：删队列、监控开关 | ❌ | ✅ | ✅ |
| Admin OpenAPI（`X-Admin-Key`） | — | — | 配置密钥 |

Web 操作 **不向 QQ 群发通知**。

### 群访问范围

- `ClanBattleMember`：用户通过 `绑定本群公会` 或管理员配置获得某 `group_id` 的 Web 访问权。
- 与 `user_account`（游戏 UID）独立，可无先后顺序。

---

## 私聊管理指令（超管）

| 指令 | 说明 |
|------|------|
| `任命管理员 QQ号` | 委派管理员 |
| `撤销管理员 QQ号` | 撤销委派 |
| `管理员列表` | 查看委派列表 |

注册于 `clanbattle/rbac_commands.py`。

---

## 开发注意事项

1. 新增 QQ 指令时明确使用 `require_ops_admin` 或公开，勿误用 `check_priv_adimin`（群管）。
2. 新增 Web 路由时在 `webui/util.py` 对齐 `resolve_role` / `GroupPriority`。
3. Admin API 使用 `api.admin_key` 头鉴权，与成员 Cookie 登录分离。
